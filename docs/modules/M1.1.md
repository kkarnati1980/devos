# M1.1 — Data model (contract)

- **Phase · lane:** P1 · Lane A · Linear DEVOS-27
- **Depends on:** G0 (closed 31 Oct 2026) · Decision Record v1.3.0 (O2: Postgres on the DevOS server) · PRD v1.1.0
- **Status:** v1.0, ready to build. KK answered Q1–Q2 on 1 Nov 2026 (end of this file).
- **Owned files:**
  - New package `packages/db/**`: `package.json`, `tsconfig.json`, `prisma.config.ts`, `prisma/schema.prisma`, `prisma/migrations/**`, `src/**`, `test/**`.
  - `.github/workflows/db.yml` (new workflow; M0.6's `ci.yml` is not touched).
  - This contract.
  - `pnpm-lock.yaml` changes from the new dependencies (shared file; dependency lines only).
- **Unblocks:** M1.2 API and auth, M1.3 dashboard shell, M1.5 run engine; later M2.4 (inventory), M3.4 (verdicts) and M4.x (deploys, health).

## Goal
One Postgres schema, managed by Prisma migrations, that holds **all DevOS state** named in the PRD:
- projects and their specs, requirements, milestones, modules and tasks;
- agent runs, checkpoints and costs;
- commits, test evidence and review verdicts;
- deploys and health;
- approvals (decision cards);
- the resource inventory, settings and vault secrets (ciphertext only);
- typed task memory, the audit trail, notifications and reports.

The integrity rules that must never depend on application code are enforced **in the database**.

**Done when:** migrations apply clean to an empty Postgres and the schema is reviewed (Linear DEVOS-27).

## Not in scope
- Business logic, the API (M1.2), the queue (M1.5) and encryption of vault values (M1.4).
- Creating the production DevOS Postgres in Coolify. That ships with the first deployable service (M1.2); this module proves the schema against Postgres in CI.
- Seed and mock data for the dashboard (M1.3).

## Decisions (Architect, under D10 — technical, logged here)
| # | Decision | Why |
|---|---|---|
| M1.1-a | Schema lives in its own package **`@devos/db`** (`packages/db`) and exports a client factory. `apps/api` and workers import it. | One owner per file. API, run engine and reports share one client without importing each other. |
| M1.1-b | **Prisma 7.10.1** (stable; the npm `latest` tag currently points at an 8.0 release candidate, which we avoid), with `@prisma/adapter-pg` and `pg`, and the **`prisma-client`** generator with an explicit `output`. The URL is read by `prisma.config.ts` from `DATABASE_URL`; it is never in the schema and never committed. | Prisma 7 requires a driver adapter and a config file. It is ESM-only, so the package is `"type": "module"`. |
| M1.1-c | **PostgreSQL 17** in CI, the same major Coolify will run. | CI matches production. |
| M1.1-d | **UUID primary keys** (`gen_random_uuid()` in the DB), `timestamptz` for every timestamp, money as `numeric(12,6)` USD, snake_case table and column names (`@@map`/`@map`), and Postgres enums for every closed set. | Stable IDs across services. Exact cost sums (M0.5 showed per-run costs around $0.005). No time-zone ambiguity, since reports use IST. |
| M1.1-e | **Nothing is cascade-deleted.** Every foreign key is `ON DELETE RESTRICT`. A project is never deleted from the DevOS DB: Purge (DV-FR-060) deletes the project's *external* resources, and the DevOS row moves to stage `PURGED` (KK, Q1). | Keeps spend history, audit trail (DV-NFR-06, 12 months) and verdicts. An accidental delete fails loudly instead of silently removing history. |
| M1.1-f | **Cost is one ledger** (`cost_entry`): one row per model per run or review, with provider, model, role and tokens. Run and project totals are sums, not copies. | Spend by role and model (DV-FR-002) and caps (O5) come from one source. This is the per-model shape M0.5 measured. |
| M1.1-g | **Status from evidence (DV-NFR-07):** requirement and module "built/tested/live" progress is *derived* from `test_evidence`, `review_verdict` and `deploy` rows. The schema stores no free-text status that an agent can set about itself. | Truthful dashboard. |
| M1.1-h | **D1 in the database:** a `deploy` row for `LIVE` must reference a `PASS` verdict for the **same project and SHA**, enforced by trigger. | A coding mistake in Release cannot ship an unreviewed commit. |

## Entities
Every table has `id uuid`, `created_at` and (where rows change) `updated_at`. FK = foreign key (indexed, RESTRICT). *Italics* mark an enum.

**Project and plan**
| Table | Key columns | Notes / constraints |
|---|---|---|
| `project` | `slug` (unique, `^[a-z0-9-]{2,40}$`), `name`, *`stage`* (intake, provisioning, building, preview, live, archived, purged), `paused_at`, `cap_usd`, `lanes` (1–3, default 2), `repo_url`, `imported_repo` (bool), `preview_url`, `live_url`, `archived_at`, `purge_after` | Stages per KK (Q2). Pause is a flag, not a stage, so stage survives pause and resume (DV-FR-061). |
| `spec` | FK project, `version`, *`source_format`* (docx, pdf, md, html, paste), `original_name`, `file_sha256`, `storage_path`, `text` | Unique (project, version). The original file stays on the server volume; the text is in the DB. |
| `requirements_doc` | FK project, `version`, `repo_path`, `commit_sha`, *`status`* (draft, approved, superseded), FK approval | Gate 1. At most one approved doc per project (partial unique index). |
| `requirement` | FK project, `key` (e.g. `DV-FR-001`), `title`, *`priority`* (must, should, could), `acceptance` (text), FK milestone | Unique (project, key). |
| `milestone` | FK project, `ordinal`, `name`, `gate_name`, `closed_at`, FK gate-evidence approval | Unique (project, ordinal). Closes only with evidence (D10). |
| `module` | FK project, FK milestone, `key` (e.g. `M1.1`), `title`, `lane`, `contract_path`, *`status`* (planned, ready, in_progress, in_review, merged, deadlocked), `merged_sha`, `linear_issue` | Unique (project, key). |
| `module_dependency` | FK module, FK depends_on module | Primary key is the pair; check `module_id <> depends_on_id`. |
| `module_requirement` | FK module, FK requirement | Many-to-many. |
| `task` | FK project, FK module (nullable for maintenance), *`kind`* (build, test, review, fix, maintenance, human), *`assignee`* (agent, kk, engineer), `title`, *`status`* (blocked, ready, running, done, failed, deadlocked), `attempts` (≥ 0), `linear_issue` | DV-FR-031 human tasks are `kind=human`. |
| `task_requirement` | FK task, FK requirement | Many-to-many. |
| `task_blocker` | FK task, FK approval | Work waits only on the cards it depends on (DV-FR-012). |

**Runs and cost**
| Table | Key columns | Notes / constraints |
|---|---|---|
| `run` | FK task, FK project, *`role`* (chief, analyst, architect, builder, tester, reviewer, release, maintainer), `model`, `attempt`, *`status`* (queued, running, succeeded, failed, limit_hit, cancelled), `max_turns`, `max_seconds`, `max_cost_usd`, `turns`, `start_sha`, `end_sha`, `branch`, `error`, `started_at`, `ended_at` | Limits stored per run (PRD run limits). |
| `checkpoint` | FK run, `seq`, `data` (jsonb) | Unique (run, seq). Resume point (DV-NFR-01). |
| `cost_entry` | FK project (nullable for global), FK run (nullable), FK review_verdict (nullable), *`provider`* (anthropic, openai), `model`, *`role`*, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `usd` (≥ 0), `occurred_at` | Exactly one of run or verdict is set (check). Indexed (project, occurred_at) for monthly caps. |

**Code, tests, review, deploys**
| Table | Key columns | Notes / constraints |
|---|---|---|
| `commit` | FK project, `sha` (`^[0-9a-f]{40}$`), `branch`, FK module (nullable) | Unique (project, sha). |
| `test_evidence` | FK commit, *`check`* (build, lint, typecheck, unit, acceptance, smoke), FK requirement (nullable), `command`, `exit_code`, `passed`, `output_ref` | Per SHA, per requirement (M3.3). |
| `review_verdict` | FK commit, `round` (≥ 1), *`reviewer`* (codex, opus_tiebreak), *`verdict`* (pass, changes_requested), `summary`, `raw` (jsonb) | Unique (commit, round). The shape matches `@devos/shared` `ReviewVerdict`. A verdict belongs to one SHA, so a new SHA has none (M3.4). |
| `review_finding` | FK review_verdict, *`severity`* (high, medium, low), `file`, `line` (≥ 0), `evidence`, `consequence`, FK follow-up task (nullable) | Low findings link to their follow-up task. |
| `deploy` | FK project, FK commit, *`environment`* (preview, live), *`status`* (pending, deploying, probation, succeeded, failed, rolled_back), FK review_verdict (nullable), FK approval (first launch, nullable), `coolify_deployment`, FK rolled_back_to deploy (nullable), `started_at`, `finished_at` | **Trigger (M1.1-h):** `environment=live` requires a verdict that is `pass` and belongs to the **same commit**. |
| `health_check` | FK project, *`environment`*, `ok`, `latency_ms`, `checked_at` | Indexed (project, environment, checked_at). |

**Approvals, inventory, settings, secrets**
| Table | Key columns | Notes / constraints |
|---|---|---|
| `approval` | FK project (nullable for global), *`gate`* (requirements, decision, first_launch, destructive_or_spend, purge), `action`, `target`, `reason`, `cost_usd`, `consequence`, *`status`* (pending, approved, rejected, expired), `decided_at`, `decided_by`, `confirmation_hash` | Check: a decided status requires `decided_at`. | `approval_comment` | FK approval, `author`, `body` | KK may comment (DV-FR-003). |
| `resource` | FK project, *`provider`* (github, coolify, cloudflare, r2, vault, backup_schedule), `kind`, `external_id`, `name`, *`status`* (active, deleted), `deleted_at` | Unique (provider, kind, external_id): create-or-get (DV-NFR-02). The teardown scan reads it (M2.5). |

| `role_model` | *`role`* (unique), `model` | Model per role (D6, DV-FR-006). |
| `notification_channel` | *`kind`* (dashboard, mybrain, email), `enabled`, `target` | O6. |
| `vault_secret` | FK project (nullable for global), `name`, `ciphertext` (bytea), `nonce` (bytea), `key_version` | Unique (project, name). **No plaintext column exists.** Encryption is M1.4. |

**Memory, audit, notifications, reports**
| Table | Key columns | Notes / constraints |
|---|---|---|
| `memory_item` | FK project, FK task (nullable), *`type`* (decision, observation, checkpoint, evidence), `content`, `source`, `observed_at`, `verified_at`, `expires_at` | DV-NFR-08: typed, sourced and timed. |
| `audit_event` | `occurred_at`, *`actor`* (agent, kk, system), *`role`* (nullable), FK project (nullable), `sha` (nullable), `cost_usd` (nullable), `action`, `summary` (plain English, for the activity feed), `details` (jsonb) | **Append-only:** a trigger rejects `UPDATE`. ## Interface (what other modules get)
- `import { createDb } from "@devos/db"` returns a Prisma client built with `PrismaPg` from a given `DATABASE_URL`. Generated types are re-exported.
- `pnpm --filter @devos/db db:migrate` runs `prisma migrate deploy` (the only way the schema changes in any environment).
- New tables or columns arrive only as new migrations in later modules. Owners of later modules extend the schema through their own PRs, which this contract's tests then also cover.

## Acceptance tests
| # | Test | Pass when |
|---|---|---|
| AT1 | Schema valid | `prisma validate` and `prisma format --check` pass |
| AT2 | Migrations apply clean | `prisma migrate deploy` on an empty Postgres 17 succeeds; a second run applies nothing |
| AT3 | No drift | `prisma migrate diff` from the migrations to the schema reports no difference (`--exit-code` = 0) |
| AT4 | Coverage | Every table in **Entities** exists with the listed unique keys and checks (asserted from `information_schema` and `pg_constraint`) |
| AT5 | Conventions | Every PK is `uuid`; every timestamp is `timestamptz`; every money column is `numeric(12,6)`; every FK column has an index; every FK is `RESTRICT` (catalogue query) |
| AT6 | Integrity | Rejected inserts: duplicate `project.slug`; bad slug; bad SHA; duplicate `(project, requirement key)`; self-dependency; negative cost; `cost_entry` with both or neither of run and verdict; second `app_settings` row; decided approval without `decided_at`; second approved `requirements_doc` |
| AT7 | D1 in the database | A `live` deploy with no verdict, a `changes_requested` verdict, or a `pass` verdict for a **different** commit is rejected; a `live` deploy with a `pass` verdict for the same commit is accepted; a `preview` deploy needs no verdict |
| AT8 | Audit append-only | `UPDATE audit_event` is rejected; `INSERT` works |
| AT9 | Client | `createDb` connects through `PrismaPg`, inserts a project and reads it back; `pnpm typecheck` passes with the generated client |
| AT10 | No secrets | `vault_secret` has no plaintext column; `DATABASE_URL` comes only from the environment; `.env.example` gets a placeholder only; no URL or credential is committed |
| AT11 | CI | (a) **Reviewer, static:** `db.yml` runs a `postgres:17` service and AT1–AT9 on PRs and pushes to `main`, with no step allowed to fail. (b) **Merge gate, live:** both the `build` (M0.6) and `db` check runs are `success` on the exact head SHA, recorded on DEVOS-27 |

**Raw-SQL objects.** Prisma's schema language does not model every database object:
- **What:** check constraints, the two triggers (AT7, AT8) and the partial unique index on `requirements_doc` go in a dedicated, commented migration.
- **AT3 must stay meaningful:** if `migrate diff` flags any of these objects, the Builder switches to Prisma's supported equivalent where one exists, or replaces the object with a trigger. AT3 is never weakened to pass, and an exception list is never added to the diff.

Root `pnpm test` (the M0.6 CI) runs only the DB-free tests (schema conventions parsed from `schema.prisma`). The Postgres tests run as `test:db` in `db.yml`, so the M0.6 workflow needs no database.

## KK decisions (1 Nov 2026)
- **Q1 — What stays after Purge: keep the records.** A purged project's DevOS records stay (name, requirements, verdicts, spend, audit trail, decision history), marked `PURGED`. Purge removes everything outside the DevOS DB: repo, stacks, volumes, secrets, backups, access.
- **Q2 — Project stages: as proposed.** Seven stages: `INTAKE` → `PROVISIONING` → `BUILDING` → `PREVIEW` (awaiting first-launch approval, gate 3) → `LIVE` → `ARCHIVED` (30 days) → `PURGED`. Pause is a separate flag (`paused_at`).
