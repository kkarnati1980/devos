## Goal
Every push to main and every PR against main runs three blocking gates on the devos repo:
1. **Secret scan** of the full git history.
2. **Dependency vulnerability scan** of `pnpm-lock.yaml`: any high or critical finding fails.
3. **Licence report and check** of every installed dependency (D13).

A fourth job, the **self-test**, proves on every run that the gates actually fail: a seeded fake secret and a pinned vulnerable package each make their gate exit 1, and their clean twins exit 0.

## Tools (D13 check)
Both are CI-only tools. They are downloaded at a pinned version, their SHA-256 is checked against the value in `.github/actions/security-tools/action.yml`, and nothing from them is shipped or vendored.

| Tool | Version | Licence | Use |
|---|---|---|---|
| gitleaks | 8.21.2 | MIT | secret scan (`gitleaks git`, default rules) |
| osv-scanner | 1.9.1 | Apache-2.0 | vulnerability scan against the OSV database (`api.osv.dev`) |

`pnpm audit` was not chosen, because npm retired the audit endpoint that pnpm 9.12 uses. The licence listing is `pnpm licenses list --json` (pnpm itself, MIT). No new package dependency.
Egress: GitHub-hosted runners only (github.com release downloads, api.osv.dev). Nothing runs on the DevOS server.

## Design
- **Wrappers** (`scripts/security/`). Each is a small Node script with a pure `evaluate` function (unit-tested offline) and a CLI that runs the tool. Exit codes: 0 = pass, 1 = gate failed, 2 = the tool itself failed (also blocks).
  - `secret-scan.mjs <repo>`: runs `gitleaks git --redact` with a JSON report. It prints only rule ID, file, line and commit for each finding, never the match or the secret, even though gitleaks already redacts.
  - `vuln-scan.mjs <lockfile>`: runs `osv-scanner --format json --lockfile`. osv-scanner exits 1 when it finds anything, so the wrapper decides by severity:
    - a group's `max_severity` (CVSS) ≥ 7.0 blocks;
    - with no CVSS, the advisory's `database_specific.severity` HIGH or CRITICAL blocks;
    - **a finding with no severity at all blocks** (fail closed);
    - medium and low findings are listed but pass.
  - `licence-check.mjs`: runs `pnpm licenses list --json` (prod + dev) and checks it against `docs/security/licence-policy.json`.
    - A permissive licence passes.
    - **Strong or network copyleft** (GPL, AGPL, SSPL, EUPL, OSL, CPAL and similar) fails. Under D13 that needs a decision card to KK, never an agent waiver.
    - **Weak copyleft** (LGPL, MPL, EPL, CDDL, CC-BY-SA) passes only for a package listed in the policy's `reviewed` entries with its version, **the same reported licence**, a reason and a reference. A new weak-copyleft package therefore fails until someone writes the assessment down, and Codex reviews that diff.
    - An unknown, missing or unparseable licence fails, including a dangling or doubled operator (`MIT OR OR GPL-3.0`, `MIT OR`). The whole expression is parsed first, so a malformed part fails it even under an outer `OR` (`MIT OR (GPL-3.0 OR)`).
    - SPDX expressions: `A OR B` passes if either side passes; `A AND B` (also "A and B") passes only if both pass.
    - The full report (licence → packages) goes to the job summary.
  - `selftest.mjs`: builds throwaway fixtures in a temp dir and runs the same wrappers on them.
    - Secret: a fresh git repo with one commit holding a fake GitHub token and a fake AWS key. Both are random, built at run time and never committed to devos. Its clean twin has an ordinary file.
    - Vulnerability: a `package-lock.json` pinning `lodash@4.17.20` (CVE-2021-23337, CVSS 7.2, high). Its clean twin pins `ms@2.1.3`.
- **Reviewed weak copyleft at v1.0.0.** Both are unmodified, separately distributed libraries, so they do not bind DevOS code:
  - `@img/sharp-libvips-*` 1.3.4 (LGPL-3.0-or-later): optional prebuilt libvips binaries pulled by Next.js `sharp`. They are dynamically loaded and unused, because the dashboard sets `images.unoptimized` (M1.3).
  - `elkjs` 0.11.1 (EPL-2.0): a Prisma Studio graph-layout dependency, used unmodified. EPL-2.0 is file-level copyleft.
- **Workflow** `security.yml`: on push to main and on PRs to main. Four jobs: `secret-scan`, `vuln-scan`, `licence-check`, `security-selftest`. Permissions `contents: read`. Tools come from the composite action.
- **Out-of-band:** none of the gates can be skipped by a label or an env flag. There is no vulnerability allowlist. A false positive is fixed by changing the code, or by KK's scoped waiver (ADR-0010), never by the agent.
- **`.gitleaksignore`** holds only commit-qualified fingerprints (`<commit>:<file>:<rule>:<line>`) of fake test fixtures in **historic commits**, which cannot be rewritten. The fixture must already be fixed in the tree. The same value in the tree or in any new commit still fails. AT4b enforces the format.
  - v1.0.0 has one entry: M1.6 AT3's fake AWS key (commit b699843), a test input that proves notices refuse secrets. The tree now builds it at run time.
- **Findings on the first run (fixed here)** — the clean-tree gate found real high findings, so they are fixed, not waived:
  - `multer` 2.4.0, GHSA-q7qp-rjg7-q26m (7.5), via `@nestjs/platform-express`;
  - `postcss` 8.4.31, GHSA-6g55-p6wh-862q and GHSA-r28c-9q8g-f849 (7.5), via `next`.
  - Fix: root `pnpm.overrides` (`multer` 2.5.0, `postcss` 8.5.32). Both are same-major updates. The api tests, the dashboard tests and `next build` stay green.

## DEVOS-197 build notes (14 Nov 2026, runner B, ADR-0013)
- **Why:** a key-like test fixture pushed to any branch turns `secret-scan` red on main and on every open PR, because CI scans the history of all fetched branches (13 and 14 Nov). The scan was right; the fault was pushing before scanning.
- **What:** `pnpm secret-scan:local [--base <ref>]` (`scripts/security/secret-scan-local.mjs`) runs gitleaks over `<base>..HEAD` only (default `origin/main`): the same pinned version, default rules and `.gitleaksignore` as CI, the same `--redact` and the same never-print-a-secret formatter (`formatFindings` from `secret-scan.mjs`). Exit 0 clean, 1 finding, 2 tool or setup failure.
- **Installer:** `node scripts/security/install-gitleaks.mjs` installs the pinned gitleaks into `~/.cache/devos-tools/gitleaks-<version>/` (or `$XDG_CACHE_HOME`). It reads the version and SHA-256 from `.github/actions/security-tools/action.yml`, so the local copy cannot drift from CI's, and verifies the checksum before unpacking. The scan uses `$GITLEAKS`, then that cached copy, then `gitleaks` on PATH, and refuses (exit 2) any binary whose `gitleaks version` is not the pinned one; `GITLEAKS_CONFIG` is removed from its environment (pre-review finding).
- **Interface:** `--base <ref>` (default `origin/main`) and `--repo <path>` (default `.`, used by the self-test); both refuse a value starting with `-`. A base the caller picks (e.g. `HEAD`) narrows the range; the default is what the runners use.
- **Pre-review:** 2 rounds, 8 findings; fixed: version pin enforced and `GITLEAKS_CONFIG` dropped (medium), exact-argv/no-commit/404 test cases, `.part` cleanup, owned files, push-only-HEAD wording, `--repo` leading `-`. Recorded, not changed: the cached binary is not re-hashed on each use (the version check covers drift; low).
- **Runner decision (technical): a new script, not a flag on `secret-scan.mjs`.** The CI scan is unchanged, so this PR cannot weaken it; the local script only reuses its formatter and evaluator.
- **Runner rule (both runners, fix rounds included):** run `pnpm secret-scan:local` before every push; exit 1 means do not push. See `docs/decisions/0024-local-secret-scan.md` for the fixture rule.
- **Split (rules.md, one concern per PR):** item 4 of DEVOS-197 (move `actions/checkout`, `actions/setup-node` and `pnpm/action-setup` to their Node 24 majors, SHA-pinned) edits every workflow including `security.yml`, a security-scanning file, so it is its own PR under DEVOS-197 (follow-up sub-issue).
