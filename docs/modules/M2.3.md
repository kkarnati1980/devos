## Goal
"Done when": **approve or reject changes project state; blocked tasks wait** while unrelated work continues.

## Decision cards (`apps/api/src/approvals.ts`)
- A **card** is one `approval` row in the **ACTION / TARGET / REASON** shape: `gate` (requirements, decision, first_launch, destructive_or_spend, purge), `action`, `target`, `reason`, optional `costUsd` and `consequence`, optional `projectId`.
- **Validation (BS-A01):** action and target 1–200 characters, one line; reason 1–2,000; consequence ≤ 2,000; `costUsd` a non-negative decimal with ≤ 6 places; UUIDs for ids; unknown fields refused; secret-shaped text refused with `card-contains-secret` (same detector as M1.6, cards are notified out of the server).
- **`raiseCard(input, { blocks: taskIds[] })`** — creates the card and its `task_blocker` rows, sets each listed task to `blocked`, writes `audit_event` `approval.raised`, all in **one transaction**; then sends one M1.6 notice of kind `approval` (title = ACTION, body = TARGET + REASON, `approvalId` set). A notification failure never undoes the card (the feed shows the failed delivery; no automatic resend, ADR-0011 §9).
- **Dedupe:** a second `raiseCard` for the same `(projectId, gate, action, target)` while a pending card exists returns that card and only adds the new blockers.
- **From policy (ADR-0006):** `cardForDecision(decision, request)` turns an M1.7 decision whose `enforcedOutcome` is `require_approval` into a card (action = request action, target = request resource, reason = decision reason, gate = the matched gate rule's `constraints.gateName` or `decision`) and blocks the requesting task. Any other outcome is refused (`card-not-required`).

## Deciding (KK only)
- **`approve(kkSession, approvalId, scope)`** and **`reject(kkSession, approvalId, comment?)`** need `verifyKkSession(session)` = true and an identity `kk:…`; otherwise `not-kk` (403). Agents and unverified sessions can never decide.
- Only a `pending` card can be decided (`card-not-pending`, 409). The decision is written with `status`, `decided_at` and `decided_by`, plus `audit_event` `approval.approved` / `approval.rejected`, in **one transaction** that locks the card row (`SELECT … FOR UPDATE`), so two concurrent decisions cannot both succeed.
- **Approve** issues exactly one grant through M1.7 `issueGrant` with `approvalId` set: `scopeAction` = card action, `scopeResource` = card target, `projectId` = card project, optional `sha` (40-hex), `expiresAt` (default 24 h, at most 90 days), `maxUses` (default 1). The grant and the card decision commit together; if `issueGrant` fails, nothing is decided.
- **Purge (gate 5)** additionally needs `confirmationHash` = SHA-256 of the typed confirmation phrase `PURGE <target>`; a mismatch is `purge-confirmation-mismatch` and nothing changes.
- **Reject** stores KK's optional comment as `approval_comment` (author `kk:…`). Rejected cards never issue grants.
- **Comments:** `comment(kkSession, approvalId, body)` on any card; 1–2,000 characters.

## Blocked tasks wait (DV-FR-012)
- A task with any blocker whose card is `pending`, `rejected` or `expired` stays `blocked`; the M1.5 scheduler only claims `ready` tasks, so unrelated tasks keep running.
- When a card is **approved**, each task it blocks becomes `ready` **only if** none of its other blockers is still pending, rejected or expired — in the same transaction as the decision.
- When a card is **rejected**, its tasks stay `blocked` and the project's milestone it gates cannot close.
- **Expiry:** `expireCards(now)` sets pending cards older than their gate's window (default 7 days) to `expired` (audited); a task blocked by an expired card stays blocked. A grant that expires before it is used leaves the work blocked: M1.7 `decide` refuses it with `grant-expired`, and the caller raises a fresh card.

## Gate engine (`apps/api/src/gates.ts`, D10)
- `closeMilestone(milestoneId, approvalId)` closes a milestone only when the approval is `approved`, belongs to the same project, and its gate equals the milestone's `gate_name`; otherwise `gate-evidence-missing` (409). The M1.1 AT18 trigger is the backstop; this check gives the friendly error first.
- Every transition is evaluated through M1.7 `decide` (action `gate.transition`, resource `milestone:<id>`); a deny stops it with the policy reason code.

## Routes (added to `apps/api/openapi.yaml`; all `session`, deny by default)
| Method + path | Who | Notes |
|---|---|---|
| `GET /approvals?status=&projectId=&cursor=` | session | Newest first, 50 per page, cursor pagination; card + blocked task count + grant summary (no grant ids beyond the card's own) |
| `GET /approvals/:id` | session | Card, comments, blocked tasks (id, title, status), grant (scope, expiry, uses/maxUses, revoked) |
| `POST /approvals/:id/approve` | KK, CSRF | Body `{ expiresInHours?, maxUses?, sha?, confirmation? }` |
| `POST /approvals/:id/reject` | KK, CSRF | Body `{ comment? }` |
| `POST /approvals/:id/comments` | KK, CSRF | Body `{ body }` |
| `POST /approvals/:id/grant/revoke` | KK, CSRF | M1.7 `revokeGrant`; audited |

Error bodies are fixed codes only (`not-kk`, `csrf`, `card-not-found`, `card-not-pending`, `purge-confirmation-mismatch`, `invalid-input`, `approvals-store-error`); a driver message is never returned or logged. A route is not retried by the client (ADR-0011 §9).

## Dashboard (`/approvals`)
- Inbox list (pending first, then decided) with ACTION / TARGET / REASON, gate, cost and blocked-task count; detail page with comments, blocked tasks, Approve (expiry and uses fields; purge asks for the typed phrase) and Reject (comment). All text is rendered escaped under the existing strict nonce CSP; forms send the CSRF token. Nav link "Approvals" with a pending count.

## Acceptance tests
| ID | What |
|---|---|
| AT1 | `raiseCard` stores the card, blocks the listed tasks, audits, and sends one `approval` notice; a failed notice still leaves the card |
| AT2 | Approve sets `approved`, issues one grant scoped to the card (action, target, project, SHA) and unblocks a task whose only blocker it was; a task with another pending blocker stays `blocked`; an unrelated `ready` task is untouched |
| AT3 | Reject sets `rejected`, stores the comment, issues no grant, and the blocked tasks stay `blocked` |
| AT4 | Approving a card consumes exactly one use when M1.7 `decide` presents its grant; a second use is refused `grant-used-up` (ADR-0006) |
| AT5 | An expired approval leaves the task blocked: an expired card keeps its task `blocked`; an expired grant is refused `grant-expired` and the task stays blocked (ADR-0006) |
| AT6 | Only KK decides: an agent identity, an unverified session or a missing CSRF token is refused (403) and nothing changes |
| AT7 | Two concurrent approvals of one card: exactly one succeeds, the other gets `card-not-pending`; one grant exists |
| AT8 | `cardForDecision` makes a card only from `require_approval`; dedupe returns the pending card and adds blockers |
| AT9 | Purge needs the matching confirmation hash; a mismatch changes nothing |
| AT10 | `closeMilestone` refuses without an approved, same-project, same-gate approval (`gate-evidence-missing`) and closes with one |
| AT11 | Input validation and secret-shaped text refused; error bodies are fixed codes |
| AT12 | Dashboard e2e: the inbox lists a pending card, Approve and Reject work, card text is escaped, and the pages send the CSRF token under the strict CSP |

AT2–AT5, AT7 and AT10 also run against Postgres (`apps/api/test-db/approvals.test.mjs`).
