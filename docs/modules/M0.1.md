# M0.1 — Server baseline (contract)

- **Phase · lane:** P0 · Lane A (critical path) · Linear DEVOS-33
- **Depends on:** H1 (server purchased) ✓ — Hostinger KVM 4 (ADR-0002), "Ubuntu 24.04 with Coolify", India, IP 200.234.41.176.
- **Owned files:** `scripts/phase0/01-server-baseline.sh` (v1.3.2; DEVOS-52 changed only the printed next steps: IPv4+IPv6 laptop check; step 2 shows the SSH tunnel until `tailscale0` exists, then the tailnet-only note — PR37-r1), this contract.

## Goal
Harden the fresh VPS and make the Coolify admin panel — and every Docker-published port — reachable **only over an SSH tunnel**, not the public internet. Conservative and reversible: no SSH lockout, no change to Coolify's own config. Permanent private access is M0.2 (Tailscale, ADR-0003).

## What the script does (idempotent, run as root)
1. `apt update && apt full-upgrade`; install + enable `unattended-upgrades`.
2. **UFW**: default deny incoming/routed, allow outgoing. Public **22/tcp** is allowed only on first setup (UFW inactive at start); on any re-run existing rules are kept as they are — no reset, no SSH rule added. Rule files are kept ASCII (ufw rewrites them as ASCII).
3. **DOCKER-USER filtering** via `/etc/ufw/after.rules`: Docker's published ports (Coolify 8000/6001/6002, proxy 80/443) bypass UFW's INPUT chain, so `DOCKER-USER` is **default-deny and stateful**: ufw route rules (tailnet, M0.2), replies (`ESTABLISHED,RELATED`) and private sources pass; every other forwarded packet to a container is dropped — any protocol, any port (v1.3.0, after Codex review). The same policy applies to IPv6 via `/etc/ufw/after6.rules` (Coolify's `coolify` network has IPv6; container ULA `fd00::/8`). The DEVOS block is replaced on re-run. Survives reboot and `ufw reload`.
4. **fail2ban** for SSH.
5. Verify Coolify runs (`docker ps`) and answers on `localhost:8000`.
6. Print an **evidence block** for G0.

## Not done here (deliberate)
- No root-login / key-only / port change — avoids lockout; optional later-hardening ADR.
- No tailnet allowance — M0.2 adds `tailscale0` access (ADR-0005: no Tailscale Serve).

The server has a public IPv6 address and Docker publishes on `[::]` via ip6tables DNAT, which bypasses UFW's v6 INPUT chain — hence the IPv6 DOCKER-USER rules. IPv6 must be tested explicitly; where a client error is ambiguous, the `ufw6-docker-logging-deny` packet counter on the server is the evidence. AT3 must run off-server: a request from the host to its own public IP does not traverse the public path and proves nothing.
