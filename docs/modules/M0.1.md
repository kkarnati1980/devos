# M0.1 — Server baseline (contract)

- **Phase · lane:** P0 · Lane A (critical path) · Linear DEVOS-33
- **Depends on:** H1 (server purchased) ✓ — Hostinger KVM 4 (ADR-0002), "Ubuntu 24.04 with Coolify", India, IP 200.234.41.176.
- **Owned files:** `scripts/phase0/01-server-baseline.sh` (v1.2.0), this contract.

## Goal
Harden the fresh VPS and make the Coolify admin panel — and every Docker-published port — reachable **only over an SSH tunnel**, not the public internet. Conservative and reversible: no SSH lockout, no change to Coolify's own config. Permanent private access is M0.2 (Tailscale, ADR-0003).

## What the script does (idempotent, run as root)
1. `apt update && apt full-upgrade`; install + enable `unattended-upgrades`.
2. **UFW**: default deny incoming, allow outgoing, allow **22/tcp** only.
3. **DOCKER-USER filtering** via `/etc/ufw/after.rules`: Docker's published ports (Coolify 8000/6001/6002, proxy 80/443) bypass UFW's INPUT chain, so inbound traffic to containers is dropped unless it comes from a private range. The same filter is applied to IPv6 via `/etc/ufw/after6.rules` (Coolify's `coolify` network has IPv6 enabled, so Docker DNATs those ports over IPv6 too; container ULA range `fd00::/8`). Container egress and replies are unaffected. Survives reboot and `ufw reload`.
4. **fail2ban** for SSH.
5. Verify Coolify runs (`docker ps`) and answers on `localhost:8000`.
6. Print an **evidence block** for G0.

## Not done here (deliberate)
- No root-login / key-only / port change — avoids lockout; optional later-hardening ADR.
- No tailnet allowance — M0.2 adds `tailscale0` access and Tailscale Serve.

## Acceptance tests (evidence stored per run)
| # | Test | Pass when |
|---|------|-----------|
| AT1 | `ufw status verbose` (server) | default deny (incoming); only 22/tcp ALLOW |
| AT2 | `iptables -S DOCKER-USER` and `ip6tables -S DOCKER-USER` (server) | both contain the docker-logging-deny DROP rules |
| AT3 | `curl -m 5` to `200.234.41.176` and `[2a02:4780:63:89c2::1]` on 8000, 8080, 6001, 6002, 80, 443 (KK's laptop, off-server) | every port times out / refused, IPv4 and IPv6 |
| AT4 | `ssh -L 8000:localhost:8000 … root@200.234.41.176` then `http://localhost:8000` | Coolify UI loads |
| AT5 | `systemctl is-enabled unattended-upgrades fail2ban` | both `enabled` |
| AT6 | `docker ps` + `curl localhost:8000` (server) | Coolify containers Up; HTTP 200/302 |
| AT7 | hPanel (KK) | a baseline snapshot of the hardened server exists |
| AT8 | After a reboot: `ufw status verbose` + `iptables -S DOCKER-USER` (server) | same as AT1/AT2 — rules persist |

The server has a public IPv6 address and Docker publishes on `[::]` via ip6tables DNAT, which bypasses UFW's v6 INPUT chain — hence the IPv6 DOCKER-USER rules. IPv6 must be tested explicitly; where a client error is ambiguous, the `ufw6-docker-logging-deny` packet counter on the server is the evidence. AT3 must run off-server: a request from the host to its own public IP does not traverse the public path and proves nothing.

## Done when
AT1–AT8 pass and the evidence is stored on DEVOS-33.
