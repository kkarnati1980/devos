# M0.1 — Server baseline (contract)

- **Phase · lane:** P0 · Lane A (critical path) · Linear DEVOS-33
- **Depends on:** H1 (server purchased) ✓ — Hostinger KVM 4, "Ubuntu 24.04 with Coolify", India.
- **Owned files:** `scripts/phase0/01-server-baseline.sh`, this contract.

## Goal
Harden the fresh VPS and lock the Coolify admin panel so it is reachable **only over an SSH tunnel**, not the public internet. Conservative and reversible — no SSH lockout, no change to Coolify's own config.

## What the script does (idempotent, run as root)
1. `apt update && apt full-upgrade`; install + enable `unattended-upgrades` (automatic security patches).
2. Install + enable **UFW**: default **deny incoming**, allow outgoing, allow **22/tcp (SSH)** only. Coolify's panel port (8000) and app ports are **not** opened publicly — public access arrives later via Cloudflare Tunnel (M0.2), which is outbound-only.
3. Install + enable **fail2ban** (basic SSH brute-force protection).
4. Verify Coolify is running (`docker ps`) and answering on `localhost:8000`.
5. Print an **evidence block** (uname, ufw status, docker ps, local Coolify HTTP check) for G0.

## Not done here (deliberate)
- No disabling of root login / SSH key-only / port change — avoids locking out a non-technical operator; optional later-hardening ADR.
- No public exposure of anything — that's M0.2 (Cloudflare Tunnel + Access, Google login).

## Acceptance tests (evidence stored per run)
- `ufw status verbose` shows default deny incoming, only 22/tcp allowed.
- From the public internet, `http://<ip>:8000` does **not** load; over `ssh -L 8000:localhost:8000 root@<ip>` it **does**.
- `systemctl is-enabled unattended-upgrades fail2ban` → both `enabled`.
- `docker ps` shows Coolify containers healthy; `curl -fsS localhost:8000` returns the Coolify UI.

## Done when
Coolify reachable only over an SSH tunnel; the evidence block above is captured and stored on DEVOS-33.
