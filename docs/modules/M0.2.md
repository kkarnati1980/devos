# M0.2 — Private access via Tailscale (contract)

- **Phase · lane:** P0 · Lane A · Linear DEVOS-30
- **Depends on:** M0.1 (acceptance complete, In Review) · ADR-0003 (Tailscale) · ADR-0004 (public SSH closure)
- **Owned files:** `scripts/phase0/02-tailscale-access.sh` (v1.1.0), this contract, `docs/decisions/0004-close-public-ssh.md`, `docs/decisions/0005-no-tailscale-serve.md`.

## Goal
Make the DevOS server reachable **only from KK's tailnet** (personal tailnet `tail03e201.ts.net`, owner KK's Google account): Coolify panel at `http://devos:8000` over the WireGuard-encrypted tailnet, SSH over the tailnet, and nothing on the public internet — including SSH, once the tailnet path is proven. `accelr8.in` is untouched. The DevOS dashboard (P1) will be served the same way.

## KK prerequisites (human, before the script)
1. Create a Tailscale account with **Sign in with Google** (Personal plan, free).
2. Install Tailscale on the iMac and the phone; sign in with the same Google account.
3. Admin console → **DNS**: MagicDNS **on**. Machines → `devos` → **Disable key expiry**.

## What the script does (idempotent, run as root)
1. Installs Tailscale from the official package repo (`tailscale.com/install.sh`) if missing.
2. `tailscale up --hostname=devos` — prints a login URL the first time; KK opens it and approves the server.
3. UFW: `allow in on tailscale0` — tailnet traffic reaches host services (SSH, Serve).
4. fail2ban: never ban tailnet addresses (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`).
5. **No Tailscale Serve** (ADR-0005): `tailscale serve reset`, then `ufw route allow in on tailscale0`. That adds an ACCEPT in `ufw-user-forward`, which the M0.1 DOCKER-USER chain consults first, so tailnet clients reach Docker-published ports (8000 panel, 6001/6002 realtime/terminal, 80/443 proxy) while public sources stay dropped.
6. Prints an evidence block.
7. **Only with `--close-public-ssh`** (run separately, after AT3 passes): removes the public `22/tcp` allow. SSH then works only over the tailnet; Hostinger's browser console is the break-glass path (ADR-0004).

## Resolved risk (run 3)
v1.0.0 used Tailscale Serve on 443/6001/6002. After a reboot tailscaled bound those ports on the tailnet IP before Docker, and `coolify` / `coolify-proxy` failed with `failed to bind host port 0.0.0.0:6001|443: address already in use`. v1.1.0 drops Serve (ADR-0005), so no port is shared between tailscaled and Docker.

## Done when
AT1–AT8 pass and the evidence is stored on DEVOS-30.
