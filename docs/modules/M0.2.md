# M0.2 — Private access via Tailscale (contract)

- **Phase · lane:** P0 · Lane A · Linear DEVOS-30
- **Depends on:** M0.1 (acceptance complete, In Review) · ADR-0003 (Tailscale) · ADR-0004 (public SSH closure)
- **Owned files:** `scripts/phase0/02-tailscale-access.sh` (v1.0.0), this contract, `docs/decisions/0004-close-public-ssh.md`.

## Goal
Make the DevOS server reachable **only from KK's tailnet**: Coolify panel over HTTPS on a tailnet hostname, SSH over the tailnet, and nothing on the public internet — including SSH, once the tailnet path is proven. `accelr8.in` is untouched. The DevOS dashboard (P1) will be served the same way.

## KK prerequisites (human, before the script)
1. Create a Tailscale account with **Sign in with Google** (Personal plan, free).
2. Install Tailscale on the iMac and the phone; sign in with the same Google account.
3. Admin console → **DNS**: MagicDNS **on**, HTTPS Certificates **enabled** (needed for `tailscale serve` HTTPS).

## What the script does (idempotent, run as root)
1. Installs Tailscale from the official package repo (`tailscale.com/install.sh`) if missing.
2. `tailscale up --hostname=devos` — prints a login URL the first time; KK opens it and approves the server.
3. UFW: `allow in on tailscale0` — tailnet traffic reaches host services (SSH, Serve).
4. fail2ban: never ban tailnet addresses (`100.64.0.0/10`, `fd7a:115c:a1e0::/48`).
5. Tailscale Serve (background, persistent): `https://devos.<tailnet>.ts.net` → `http://127.0.0.1:8000` (Coolify panel), plus HTTPS on 6001/6002 → Coolify realtime/terminal.
6. Prints an evidence block.
7. **Only with `--close-public-ssh`** (run separately, after AT3 passes): removes the public `22/tcp` allow. SSH then works only over the tailnet; Hostinger's browser console is the break-glass path (ADR-0004).

## Acceptance tests
| # | Test | Pass when |
|---|------|-----------|
| AT1 | `tailscale status` (server) | server online as `devos`; iMac + phone listed |
| AT2 | iMac on tailnet: browse `https://devos.<tailnet>.ts.net` | Coolify login loads with a valid TLS cert |
| AT3 | iMac on tailnet: `ssh root@devos` | shell opens |
| AT4 | Phone **with Tailscale off**, mobile data: `https://devos.<tailnet>.ts.net` | does not resolve / does not connect |
| AT5 | After `--close-public-ssh`: iMac `nc -vz -w 5 200.234.41.176 22` with Tailscale **off** | times out; AT3 still passes with Tailscale on |
| AT6 | M0.1 AT3 port loop re-run (IPv4) + v6 drop counter | still all blocked |
| AT7 | `ufw status verbose`, fail2ban `ignoreip` (server) | tailscale0 allowed; tailnet ranges ignored |
| AT8 | Reboot server | AT1, AT2, AT3 still pass (tailscaled + serve config persist) |

## Known risk (spike)
Docker's published 443/6001/6002/8000 are DNAT'd for every local address. Serve traffic is expected to be handled inside `tailscaled` before it reaches the kernel's NAT. AT2 proves or disproves this. **Fallback:** move Serve to an unpublished port (e.g. `--https=8443`) and log it. Coolify realtime warnings over Serve are acceptable for P0 if the panel works; they are logged, not blocking.

## Done when
AT1–AT8 pass and the evidence is stored on DEVOS-30.
