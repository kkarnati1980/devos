## Goal
The DevOS HTTP API (NestJS 11 on Express 5) with one way in: KK's live Tailscale identity plus a 12-hour session bound to it. Everything else is refused by default.

## Identity
- No Tailscale Serve (ADR-0005), so there is no `Tailscale-User-Login` header. The API asks the local `tailscaled` who owns the TCP peer: LocalAPI `GET /localapi/v0/whois?addr=<peer ip:port>` over the unix socket (`DEVOS_TAILSCALE_SOCKET`, default `/var/run/tailscale/tailscaled.sock`), with a hard timeout.
- Only the **socket peer address** is used. `X-Forwarded-For` and similar headers are ignored (`trust proxy` off).
- The login must equal `DEVOS_KK_LOGIN` (case-insensitive). Tagged nodes (no user), non-tailnet peers (whois 404) and other tailnet users are refused (403 `not-kk`). If tailscaled errors or times out, the request is refused with 503 `identity-unavailable` (fail closed).
- KK's policy identity is `kk:<login>` (M1.1-j).
- **Deploy requirements (recorded for the deploy module, not done here):** publish the API port directly on the host (DNAT keeps the tailnet source address; ADR-0005 UFW route rule) rather than behind a reverse proxy, and mount the tailscaled socket read-only into the container. If a proxy is put in front later (M1.3 HTTPS decision), a trusted-proxy rule must be added first; until then the API refuses every request whose peer is not KK's node.

## Session (ADR-0011 §3)
- `POST /auth/session` (sign-in) needs KK's live identity and an allowed Origin. It issues a new session every time: a random 256-bit id (rotation), `login`, `iat`, `exp = iat + 12 h`.
- The cookie value is `base64url(claims).base64url(HMAC-SHA256(DEVOS_SESSION_KEY, claims))`. Flags: `HttpOnly; SameSite=Strict; Path=/; Max-Age=<time left>`, plus `Secure` and the `__Host-` name when `DEVOS_COOKIE_SECURE=1` (after M1.3 decides browser-trusted HTTPS).
- **Absolute lifetime:** a session is refused from `iat + 12 h` on, however recently it was used; nothing extends it. `exp` must equal `iat + 12 h` exactly.
- Every request re-checks the live whois login, and it must equal the session's login: a stolen cookie is useless from another tailnet user or a non-tailnet peer.
- Sign-out (`DELETE /auth/session`) clears the cookie. Server-side revocation of a single session is not in scope: a key rotation ends all sessions.

## CSRF (ADR-0011 §1, BS-A03)
On every state-changing method (anything but GET, HEAD, OPTIONS), in this order:
1. `Sec-Fetch-Site`, when present, must be `same-origin` or `none` → else 403 `csrf-cross-site`.
2. `Origin` must be in `DEVOS_ALLOWED_ORIGINS` (exact match; `null` is refused). Without `Origin`, the `Referer`'s origin must be. Neither present → 403 `csrf-origin-missing`.
3. After identity and session, header `X-Devos-Csrf` must equal `HMAC-SHA256(key, "csrf\n" + sid)` (per session; returned by sign-in and `GET /auth/session`) → else 403 `csrf-token-invalid`. Sign-in has no session yet, so only checks 1–2 apply to it.
Plus the SameSite=Strict cookie.

## Headers, logs, timeouts
- **Security headers** on every response, including 404s and errors: `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: no-store`, `X-DNS-Prefetch-Control: off`, `X-Permitted-Cross-Domain-Policies: none`; `Strict-Transport-Security` when secure; no `X-Powered-By`. (The API serves JSON only; the dashboard's own CSP is M1.3.)
- **Request IDs and JSON logs:** an incoming `X-Request-Id` matching `[A-Za-z0-9._-]{8,64}` is kept, otherwise a UUID is generated; it is echoed in the response. One JSON line per request: `ts, level, msg, requestId, method, path (no query), status, durationMs, identity`. Never cookies, tokens, bodies, query strings or configuration values.
- **Timeouts (ADR-0011 §9):** the whois call (`DEVOS_OUTBOUND_TIMEOUT_MS`, default 3 s, 100 ms–30 s) and the readiness database probe (`SELECT 1`, same limit). The M1.7 store bounds its own transactions. No retries in the API.
- Request bodies: JSON only, 64 KB maximum.

## Routes (`apps/api/openapi.yaml`, OpenAPI 3.1, is the contract)
| Route | Access | Notes |
|---|---|---|
| `GET /health` | open | `{status, sha, startedAt}` (`GIT_SHA` env) |
| `GET /ready` | open | 200 when the database answers in time; 503 `not-ready` |
| `POST /auth/session` | tailnet | Sign-in → 201 `{login, expiresAt, csrfToken}` + cookie |
| `GET /auth/session` | session | Current session and CSRF token |
| `DELETE /auth/session` | session | Sign-out, 204 |
| `POST /grants` | session | **Approval route.** Validated `GrantScope` (unknown fields refused) → `PolicyEngine.issueGrant`; engine `grant-*` codes → 400; engine/database failure → 503 |
| `POST /grants/{id}/revoke` | session | UUID id → `PolicyEngine.revokeGrant` |

- **KK sessions for M1.7:** the API mints a frozen `KkSession` per request that passed identity, session and CSRF checks, and records it in a process-local `WeakSet`. Its `verify` is the engine's `verifyKkSession` hook, so a session object built anywhere else (an agent, a copy, a deserialised value) is refused (`grant-issuer-session-unverified`).
- Without `DATABASE_URL` and `DEVOS_POLICY_HMAC_KEY`, grant routes answer 503 `policy-engine-not-configured` and `/ready` is 503.

## Configuration (names only; values live in Coolify env / the server vault)
`DEVOS_KK_LOGIN`, `DEVOS_SESSION_KEY` (≥ 32 bytes), `DEVOS_ALLOWED_ORIGINS` (comma-separated exact origins), `DEVOS_COOKIE_SECURE`, `DEVOS_TAILSCALE_SOCKET`, `DEVOS_OUTBOUND_TIMEOUT_MS`, `DATABASE_URL`, `DEVOS_POLICY_HMAC_KEY` (≥ 32 bytes, M1.7), `GIT_SHA`, `HOST`, `PORT`. A bad value stops start-up with a code, never the value.
