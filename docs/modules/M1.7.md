## Goal
One policy decision point. Every consequential action (a tool call, a write, a push, a deploy, a metered model call, a gate transition) is evaluated as **identity + action + resource + evidence + envelope + approval + budget** and gets `allow`, `deny` or `require_approval`. The decision is stored as a hash-chained, HMAC-authenticated receipt **before** the caller sees it.

## Interface (`@devos/policy`)
- `new PolicyEngine({ store, hmacKey, budgets?, now?, verifyKkSession? })`
  - `hmacKey`: at least 32 bytes, from the server vault / Coolify env (never the repo or chat). Shorter → constructor throws.
  - `store`: `PrismaPolicyStore(createDb(url))` in DevOS; `MemoryPolicyStore` for tests and local tools.
  - `budgets`: ceilings `{ id, provider?, projectId?, runId?, maxCostUsd, maxTokens, periodMs? }`. The caller (M1.5) builds them from project caps and the O5 provider caps.
  - `verifyKkSession(session)`: the API's check (M1.2) that the session is KK's Tailscale identity. Without it nobody can issue or revoke grants.
- `decide(request) → PolicyDecision` — `{ outcome, enforcedOutcome, wouldBlock, reason, mode, matchedRuleIds, approvalGrantId, reservationId, stop, receipt }`. The caller acts on **`enforcedOutcome`** only. If `decide` rejects (database down, chain conflict), the caller treats it as deny.
- `issueGrant(kkSession, scope)`, `revokeGrant(kkSession, id)`, `reconcile(reservationId, actualUsd, actualTokens)`, `release(reservationId)`, `verify(chain = "main")`.
- Pure helpers: `evaluateRules`, `checkEnvelope`, `envelopeWidening`, `delegateEnvelope`, `grantProblem`, `sealRow`, `verifyLedger`, `canonicalize`.

## Behaviour
1. **Validation:** identity id/type (`agent | kk | system`) and action type are required; `costUsd`, `tokens`, `concurrency` must be finite and ≥ 0. Invalid → throws (no decision).
2. **Envelope first** (when the request carries the run's envelope, loaded by M1.5 from `capability_envelope`): expired, a tool not listed, a read path outside read ∪ write paths, a write path outside write paths, a non-canonical path (`..`, `.`, leading `/`, control characters), network when not allowed or a host outside the allow-list, cost/tokens/concurrency above the limits → `deny`, **enforced in every mode**.
3. **Rules** (`policy_rule`, enabled, highest version per name): empty match lists match anything; `*` and `prefix*` wildcards. Precedence **deny > require_approval > allow**, then **default deny** for an unmatched action. Ties by priority, then id.
4. **Mode** (`policy_state.mode`, default `observe` until KK approves `enforce` at G3): in `observe`, `enforcedOutcome` is `allow` and `wouldBlock` is true for a deny or approval requirement — except for **gate rules** (`constraints.gate = true`: the five gates, Release SHA checks, migration holds, the D7 PreToolUse deny hook), which are enforced in every mode. **Every matching gate binds**, whichever rule decides the outcome: a gate deny anywhere in the match set enforces deny; otherwise a gate approval requirement enforces `require_approval` (a non-gate rule can never mask a gate). A grant can then lift that requirement while the non-gate deny stays recorded as would-deny.
5. **Approval:** only a `require_approval` outcome can be lifted, by a presented `approval_grant` that is: issued by `kk:…`, not issued by the requester (no self-approval), not revoked, not expired, `uses < max_uses`, and in scope (action, resource, project, SHA). The use is counted in the same transaction. A rejected grant leaves the outcome and appends the reason (`grant-expired`, `grant-revoked`, `grant-used-up`, `grant-self-approval`, `grant-scope-*`, `grant-not-found`).
6. **Grants are issued only by KK:** `issueGrant` needs an identity of type `kk` with id `kk:…` **and** `verifyKkSession` = true. Expiry must be in the future and at most 90 days away; `maxUses` an integer ≥ 1; `sha` 40-hex when set.
7. **Fail-closed budgets** (enforced in every mode): an action with `budgeted: true` must declare `costUsd`, `tokens` (an integer) and `provider`, or it is denied (`budget-metering-required:*`, `budget-provider-required`). For each matching ceiling, open reservations + reconciled actuals (released rows count zero) + this request must stay within `maxCostUsd` and `maxTokens`, or it is denied (`budget-exceeded:<id>`). USD amounts are rounded **up** to the micro-dollar (the `Decimal(12, 6)` scale) before the check, and that same amount is stored; actuals round up on reconcile; ceilings round down. Comparisons are in integer micro-dollars. An allowed budgeted action inserts a `budget_reservation` in the same transaction. After the call the caller reconciles actuals, or releases the reservation if the call never ran.
8. **Stops:** an enforced deny sets `stop` = `policy_denied` (policy) or `budget_exceeded` (budget). M1.5 records it as a `run_error` with `counts_as_attempt = false` (the M1.1 check already enforces this), pauses at the last checkpoint and raises a card. It never advances the Sonnet → Sonnet → Opus ladder or the 3-attempt rule.
9. **Receipts:** one `policy_decision` row per decision. `hash` = SHA-256 (64 hex) of the canonical JSON of every other stored column (chain, seq from 1, ts, project/run ids, identity, action = `{ request, evidence, reason, mode, reservationId }`, outcomes, matched rule ids, grant id, bundle hash = SHA-256 of `{mode, rules}`, prev hash). `hmac` = HMAC-SHA256(key, hash). `verify` recomputes every hash and MAC and checks gapless seq and prev-hash links.
10. **Persist before answer:** evaluation of approvals and budgets, the grant use, the reservation and the receipt run inside one Postgres transaction that first takes `pg_advisory_xact_lock(hashtext('devos:policy-engine'))`; `decide` resolves only after it commits. Any failure rolls back all of it and `decide` rejects.

## Acceptance tests
Unit tests (`packages/policy/test/policy.test.mjs`, run by `pnpm test` in CI `build`) against `MemoryPolicyStore`; Postgres tests (`packages/policy/test-db/`, workflow `policy-db`) for the starred items against `PrismaPolicyStore`.

| # | Pass when |
|---|---|
| AT1 | Deny overrides allow and approval: a matching deny wins even with a valid grant; approval beats allow |
| AT2 | An unmatched action is `outcome=deny`, `enforcedOutcome=allow`, `wouldBlock` and recorded with mode `observe`; in `enforce` it is denied |
| AT3 | A child envelope cannot widen tools, read/write paths (incl. traversal), network or its allow-list, cost, tokens, concurrency, expiry or depth (parent + 1, max 3); `delegateEnvelope` throws on any widening |
| AT4* | Self-approval, expired, revoked, over-`maxUses` and out-of-scope (project, SHA) grants fail; agents and unverified sessions cannot issue; expiry > 90 days refused — all also against `PrismaPolicyStore` |
| AT5 | A budgeted request without a cost or token figure is denied, also in observe mode |
| AT6* | 20 concurrent budgeted decisions never reserve above the ceiling (exactly ⌊ceiling/cost⌋ allowed); the chain stays gapless; reconcile/release frees headroom; sub-micro-dollar costs round up so repeated calls cannot pass a ceiling at zero |
| AT7* | Changing one byte of any receipt column, hash or MAC, dropping a receipt, or using another key fails verification; the table rejects update and delete |
| AT8* | The row exists when `decide` resolves; a failed write rejects `decide` and rolls back the reservation |
| AT9 | Gate rules and envelope violations (path, tool, network host, cost, expiry) are enforced in observe mode, also when a higher-priority non-gate rule matches; a non-gate rule is only observed |
| AT10 | `THIRD_PARTY_NOTICES.md` names ruflo, the full commit and the full MIT text; each adapted file has the header; nothing from product-plane, MetaHarness or federation |
