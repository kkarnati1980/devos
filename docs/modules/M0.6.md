## Status and review scope
The scaffold was built on 29 Oct 2026, with CI green on a then-current commit. Repo history was later consolidated, so it now lives in the root commit `76cacce`. It predates the Codex reviewer (M0.3), so it has never had a review. This contract is written retroactively, and this PR also fixes the gaps found while writing it (below).

**Review scope:** the Reviewer judges the **owned files as they stand at the head commit**, not only the diff. The diff is the contract plus the fixes; the scaffold itself is unchanged since the root commit.

## Goal
One monorepo for DevOS:
- `apps/dashboard` (Next.js, from M1.3), `apps/api` (NestJS + Prisma, from M1.2) and `packages/shared` (types shared by both).
- A CI that every PR must pass.
- **One rulebook**, `rules.md`, from which `CLAUDE.md` (Claude) and `AGENTS.md` (Codex) are generated so they can never drift.

**Done when:** CI is green on the empty build.

## Design
- **Toolchain:** pnpm workspaces (`apps/*`, `packages/*`), pnpm pinned by `packageManager: pnpm@9.12.0`, Node 22 (`.nvmrc`, `engines >=22`), TypeScript 5.6 with a strict shared `tsconfig.base.json` (NodeNext, `noUncheckedIndexedAccess`).
- **Root scripts:** `build`, `typecheck`, `lint` and `test` run across all packages (`pnpm -r --if-present`). `test` also runs the root tests in `scripts/test/`.
- **Rules:**
  - `pnpm gen:rules` writes `CLAUDE.md` = banner + `rules.md`.
  - It writes `AGENTS.md` = banner + `rules.md` + a Codex review section.
  - `pnpm check:rules` exits 1 if either generated file differs from what `rules.md` would generate.
- **CI** (`.github/workflows/ci.yml`):
  - Triggers on pushes to `main` and on PRs to `main`; a newer run cancels an older one on the same ref.
  - Steps: checkout, pnpm 9.12.0, Node from `.nvmrc` with the pnpm cache, then `pnpm install --frozen-lockfile`, `check:rules`, `typecheck`, `lint`, `test`.
- **`packages/shared`:**
  - `DEVOS_VERSION`.
  - The Codex verdict types `ReviewVerdict` and `ReviewFinding`, with **exactly** the fields of the review runner's schema (M0.3): `{verdict PASS|CHANGES_REQUESTED, sha, summary, findings[{severity high|medium|low, file, line, evidence, consequence}]}`.
  - `AGENTS.md` points Codex at this.
- **Secrets:**
  - `.env.example` holds placeholders only; real values live in the server vault or Coolify.
  - `.gitignore` excludes `.env` and `.env.*` (but keeps `.env.example`), plus `node_modules`, `dist`, `.next`, `coverage`, `*.tsbuildinfo` and `.claude/worktrees/`.
- **Licence:** proprietary (`LICENSE`), © Kishore Karnati / Kiot Innovations. No third-party code is vendored.

## Fixes in this PR (found while writing the contract)
1. **Verdict type drift:** `ReviewVerdict` lacked `summary` and `ReviewFinding` lacked `line`, so the types did not match the schema the M0.3 runner enforces and AGENTS.md cites. Both fields are now added, and the field sets are exported as constants.
2. **Placeholder test:** the only test was a `1 + 1` smoke test. There are now real tests:
   - `packages/shared/test/smoke.test.js` checks the verdict types against the schema field set. It reads the source, so it needs no build.
   - `scripts/test/gen-rules.test.mjs` checks that the committed files are in sync, that a hand edit to `CLAUDE.md` or `AGENTS.md` fails `--check`, that a `rules.md` change without regeneration fails `--check` and `gen:rules` repairs it, and that the banner and Codex section are present.
3. **Stale README:** it named a KVM 8 and Cloudflare Access. It now says KVM 4 (ADR-0002) and tailnet-only private access (ADR-0003/0004/0005).

## Known limits (not defects of this module)
- **`lint` is a no-op until real code exists.** No package defines a `lint` script yet, so the CI step passes trivially. ESLint (or Biome) arrives with the first code modules, M1.2 (api) and M1.3 (dashboard), whose contracts must add a `lint` script.
- **`build` is not a CI step.** Typecheck covers the empty build. CI adds `build` once an app produces artefacts (M1.2/M1.3).
- **Branch protection on `main`** (required CI and review checks) is still to be enabled by KK. The agent proxy blocks that API, and it is tracked for G0. Until then, merges are pinned to the reviewed SHA by hand: `gh api …/merge -f sha=<reviewed sha>` after CI is green.
