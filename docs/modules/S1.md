## Goal
Put the build standard in the repo as data that later modules use:
- the selector (S5) reads the index and the signals;
- the template (S3) maps add-ons to module IDs;
- the readiness runner (S6) runs the checks by ID;
- the review rule pack (S9) cites them.

No app behaviour changes in S1.

## Design
- **One source:** `build-standard.yaml`. `pnpm gen:standard` renders `index.md` and one file per module, so the index and the module texts cannot drift from the data. `pnpm check:standard` (in CI) fails on:
  - a schema error;
  - a catalogue-rule error;
  - a generated file that is out of date or edited by hand;
  - a stray file in `modules/`;
  - an index over budget.
- **Module record:**
  - `id`, `name`, `kind` (`floor` | `selectable` | `opt_in`), `applies_when`.
  - **Floor:** `purpose`, `blocks: [preview, live]` and `checks`.
  - **Selectable:** `lite` and `full`, each with a summary and checks.
  - **Opt-in:** `checks` only.
  - **Every check:** an ID (`F2-2`, `SM-02-L2`, `SM-03-F1`), `how` (`auto` | `review` | `both`) and an evidence kind from a fixed list.
- **Signals:** regular expressions on changed paths or added code lines. They are hints for the S5 detector, which tunes them; S1 only guarantees that every pattern compiles, and that every selectable module has at least one signal entry. SM-10's only signal is the spec (set by the Analyst), so its code list is empty.
- **Token budget:** the index is estimated at 1 token per 3.5 characters, which overestimates real BPE counts for English Markdown. Budget: 2,000. Current: about 1,650.

## Acceptance tests (`scripts/test/standards.test.mjs`, run by `pnpm test`)
| # | Pass when |
|---|---|
| AT1 | The YAML validates against `build-standard.schema.json` and the catalogue rules (ID set, kinds, check-ID format, unique IDs, compiling regexes) |
| AT2 | Exactly F1–F3, SM-01–SM-18 and SM-C1–C3. Every module has an applicability test. Every selectable module has Lite and Full checks, evidence and signals. Every floor module blocks both preview and live |
| AT3 | The validator rejects 8 seeded breakages: no Full level, a floor module not blocking preview, a duplicate ID, a missing module, a check ID at the wrong level, an unknown evidence kind, a bad regex, a selectable module without signals |
| AT4 | `index.md` is at most 2,000 estimated tokens and lists every module ID |
| AT5 | Every generated file exists and matches the YAML (24 module files); `check:standard` exits 0 |
| AT6 | `rules.md` has the build-standard section; the review guidelines cite module/check IDs; both ADR files exist; `check:rules` is green (CI) |

**Also checked by hand:** appending a line to `modules/F2.md` makes `check:standard` exit 1, and so does an extra file in `modules/`.
