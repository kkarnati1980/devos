# M0.4 — Coolify API spike (contract)

- **Phase · lane:** P0 · Lane A (critical path) · Linear DEVOS-29
- **Depends on:** M0.1 ✓, M0.2 ✓ (both In Review) · KK: Coolify API enabled + API token
- **Owned files:** `scripts/phase0/04a-coolify-api-discover.sh` (v1.0.3), `scripts/phase0/04b-coolify-api-lifecycle.sh` (v1.0.5), `scripts/phase0/lib/coolify-version.sh` (v1.0.0), `scripts/test/coolify-version.test.mjs`, this contract.
- **Unblocks:** M2.4 Provisioner, M3.5 Preview pipeline (critical path).

## Goal
Prove DevOS can drive Coolify **only through its API**, repeatably: **create** an app, **deploy** it, **roll back** to the previous version, and **delete** it, leaving nothing behind. If any of the four can't be done by API, choose the fallback (Dokploy) per G0 and log it.

## Approach (two stages, because Coolify 4.5.3 is newer than the Architect's reference docs)
- **04a discover:** stores the token in a root-only file (hidden prompt; never echoed, never in chat), calls `GET /api/v1/version`, lists servers/projects, and extracts the **installed** OpenAPI spec from the `coolify` container. It prints the exact paths and fields for the operations below. Read-only; creates nothing.
- **04b lifecycle:** written from 04a's output against confirmed paths. Test app: public image `nginx:1.26-alpine` → `nginx:1.27-alpine`, in project `devos-spike-m04`; no domain, nothing public (M0.1/M0.2 filters apply).

## Lifecycle under test
1. Create a project (or reuse) and an app from a Docker image (v1 = 1.26) — no deploy.
2. Deploy; poll the deployment until finished; the container runs image 1.26.
3. Update the image tag to 1.27; deploy; the container runs 1.27.
4. **Rollback:** use the API's rollback if it exists; otherwise set the tag back to 1.26 and redeploy. The container runs 1.26.
5. Delete the app (with volumes and cleanup); no container, volume or network for it remains.
6. Run the whole thing twice: the second run passes too (repeatable).

## Fallback
If create, deploy, rollback or delete cannot be done by API: log it as an ADR, open a Dokploy spike, and keep the evidence.

## Findings (run 3, 31 Oct 2026 — Coolify 4.5.3) — input for M2.4 Provisioner / M3.5 / M4.2
- **Auth:** `Authorization: Bearer <token>`; token abilities read + write + deploy suffice. API access must be enabled in Settings → Access and API.
- **Create:** `POST /applications/dockerimage` — required `project_uuid`, `server_uuid`, `docker_registry_image_name`; we also send `environment_name`, `docker_registry_image_tag`, `ports_exposes`, `name`, `instant_deploy:false`, `autogenerate_domain:false`, `docker_images_to_keep:3`. Returns `{uuid}`.
- **Deploy:** `POST /deploy?uuid=<app>&force=true` (query params only: tag, uuid, force, pr, pull_request_id, docker_tag). Returns `deployment_uuid`; poll `GET /deployments/{uuid}` → `in_progress` → `finished`.
- **Update:** `PATCH /applications/{uuid}` `{docker_registry_image_tag}`, then deploy.
- **Rollback (native):** `GET /applications/{uuid}/rollback-images` → `{current, images:[{tag,is_current,source}]}`; `POST /applications/{uuid}/rollback` `{"commit":"<tag>"}` (the field is named `commit` even for image apps) → `{deployment_uuid}`. Needs `docker_images_to_keep` ≥ 2.
- **Delete:** `DELETE /applications/{uuid}?delete_configurations=true&delete_volumes=true&docker_cleanup=true&delete_connected_networks=true` → containers, volumes and networks gone within 5 s; `GET` → 404. `DELETE /projects/{uuid}` → 200 once empty.
- **Timing (nginx alpine, images cached after round 1):** create 0 s, deploy 10–11 s, update 15–21 s, rollback 16 s, delete 5 s; full cycle 47–52 s.
- **Follow-up:** set Coolify "Allowed IPs" to the server + tailnet once the API's observed source address is confirmed (left empty for the spike; the API is not reachable publicly).

## Follow-up DEVOS-54 (11 Nov 2026) — low notes from the Opus tie-break on `6db46b4`
Decisions (runner A, technical, per ADR-0013):
1. **Version parsing.** 04a no longer strips quotes from the raw body. `lib/coolify-version.sh` parses the `/version` body as JSON: a JSON string (`"4.5.3"`, what 4.5.3 returns) or an object with a `version` field (`{"version":"4.5.3"}`); a non-JSON body is read as bare text. AT1 still needs HTTP 200 and `^v?4.5.<n>`. Covered by `scripts/test/coolify-version.test.mjs` (runs in `pnpm test`).
2. **Rollback without `deployment_uuid`.** 04b now logs a 2xx rollback reply that has no `deployment_uuid` instead of skipping the wait silently. AT5 is still decided by `expect_image` (the container must run the v1 image).
3. **AT6 "API 200" vs `need` (any 2xx).** The contract is reworded to "API 2xx" rather than the script tightened. Reason: the recorded runs passed with `need`; the app-delete status code was not recorded in the run-3 findings, and an untestable tightening here (no server access from the runner) could turn a working spike red for no safety gain. The real gate is the leftover scan plus `GET → 404`, which are unchanged.
4. **04b's dependence on 04a.** 04b now runs the same AT1 check (`GET /version`, HTTP 200, 4.5.x) itself before any write, so a changed token or upgraded Coolify stops it before it creates anything. It still needs 04a's token file and installed spec.
These are spike scripts; M2.4 Provisioner owns the production client and should reuse decisions 1 and 4.
