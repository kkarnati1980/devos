## Goal
"Done when": **the pilot spec converts with every FR ID intact.** One call turns an uploaded spec file into structured text (headings, paragraphs, lists, tables) plus the list of requirement IDs it contains, or refuses it with a fixed reason code. M2.2 (Analyst) reads the result; the `spec` row fields come ready-made.

## Interface (`@devos/intake`)
- `ingest(bytes, originalName, options?) → Promise<IngestResult>` — the entry point for DevOS. Checks size and type in the caller, then parses in an **isolated worker** (below). Rejects with `IngestError { code }`.
- `parseSpec(bytes, originalName, options?) → IngestResult` — the same pipeline in-process (tests, the worker itself, the `check-spec` CLI).
- `IngestResult = { format, sha256, byteLength, blocks, text, requirementIds, warnings, specRow }`
  - `format`: `docx | pdf | md | html` (the `spec_format` value; `paste` text is ingested as `md`).
  - `blocks`: `heading {level 1–6, text}` · `paragraph {text}` · `list-item {text, ordered, depth}` · `table {rows: string[][]}` · `code {text}`.
  - `text`: the blocks rendered as Markdown, **inert** (PR30-r1): `&`, `<` and `>` in source text are written as `&amp;`, `&lt;`, `&gt;`, and every character that can open a Markdown construct (`\ ` * _ [ ] ( ) ! | ~ { } $ ^`, plus `# + - = :` and `1.`/`1)` at the start of a block) is backslash-escaped. No image, link, reference definition, footnote, emphasis, code span, table, math, HTML or block marker can form from spec text, and a CommonMark renderer shows the original characters. Code blocks keep their text literally inside a fence longer than any backtick run in them (only `&<>` become entities). A bare `https://…` URL stays plain text, which some GFM renderers show as a clickable link; such a link can only be `http(s)`/`www`, never `javascript:` or an image. `blocks` keep the unescaped text.
  - `requirementIds`: unique IDs in first-seen order, with a count each (below).
  - `warnings`: fixed codes only (e.g. `pdf-filter-unsupported`, `pdf-text-encoding`, `docx-tracked-deletions-skipped`); never source text.
  - `specRow`: `{ sourceFormat, originalName, fileSha256, text }` for the M1.1 `spec` row (M2.2 adds `projectId`, `version`, `storagePath`).
- `extractRequirementIds(text, prefixes?)`, `renderMarkdown(blocks)`, `DEFAULT_LIMITS`, `IngestError`.
- CLI `node packages/intake/dist/cli.js <file>` (`pnpm --filter @devos/intake run check-spec -- <file>`): prints format, block counts, warnings and every requirement ID with its count; exit 0 on success, 2 on a refusal (the code only; an unreadable or missing file is `file-unreadable`, with no path or library message, PR30-r2). This is the G2 evidence tool for the pilot spec.

## Behaviour
1. **Size first:** an empty file is `empty`; a file over `maxBytes` (default **10 MiB**) is `too-large`, before any parsing.
2. **Magic-byte type check:** the format comes from the extension (`.docx`, `.pdf`, `.md`/`.markdown`/`.txt`, `.html`/`.htm`) and must agree with the bytes; a mismatch is `type-mismatch`, an unknown extension `type-unknown`.
   - `.docx`: starts `PK\x03\x04` and the archive holds `[Content_Types].xml` and `word/document.xml`.
   - `.pdf`: `%PDF-` within the first 1,024 bytes.
   - `.md`/`.html`: valid UTF-8 (a BOM is dropped), no NUL byte, and none of the binary signatures (ZIP, PDF, ELF, PE `MZ`, PNG, GIF, JPEG, gzip, 7z, RAR, OLE). A renamed binary is therefore refused.
3. **Archive-bomb limits (`.docx`),** from the ZIP central directory before inflating anything: ≤ 2,000 entries; only `stored` and `deflate`; no encryption, no ZIP64, no multi-disk (`zip-unsupported`); each entry's declared size ≤ 50 MiB and declared total ≤ 100 MiB; compression ratio ≤ 100:1 for any entry over 1 MiB (`archive-bomb`). Only `word/document.xml`, `word/styles.xml` and `[Content_Types].xml` are inflated, with `maxOutputLength` = the declared size, and the output must equal the declared size and CRC-32 (`zip-corrupt`), so a lying header cannot inflate past its limit.
4. **Parse in the sandbox:** `ingest` parses in a `worker_threads` worker with its own heap cap (`maxOldGenerationSizeMb` 256) and a wall-clock limit (default 20 s); on expiry the worker is terminated (`parse-timeout`); on heap exhaustion `parse-memory`; any other worker failure `parse-failed`. The worker gets a copy of the bytes and returns plain data; it has no file or network access by design (it is only given bytes). M3.1 (Sandbox runner) may later move this into the container sandbox without changing the interface.
5. **Formats:**
   - **Markdown:** ATX and setext headings, pipe tables (the delimiter row dropped), ordered/unordered list items with depth, fenced code, paragraphs. Raw `<script>`/`<style>` blocks **outside fenced code** are removed; an unterminated opener removes only the tag, never the text after it (PR30-r2); fenced code is kept verbatim (a fence closes only on a line of the same character, at least as long, indented ≤ 3 spaces and followed only by whitespace — CommonMark, PR30-r3); any other HTML is kept as escaped text.
   - **HTML:** active content is never kept: `script`, `style`, `template`, `noscript`, `iframe`, `object`, `embed`, `svg`, `math`, `canvas`, `form` controls, and every attribute (so `on*` handlers and `javascript:` URLs) are dropped. `h1`–`h6`, `p`, `li` (in `ul`/`ol`, with depth), `table`/`tr`/`th`/`td`, `pre`, `br`, `blockquote` and `div` boundaries become blocks. Entities are decoded, then the text is re-escaped on render (inert).
   - **DOCX:** paragraphs from `word/document.xml`; a heading when its style is `Title` (level 1) or `Heading1`–`Heading6`, or a custom style whose `styles.xml` name is `heading N`/`Title`; list items from `w:numPr` (depth = `w:ilvl`); tables to rows of cell text; text from `w:t`, `w:tab`, `w:br`, `w:noBreakHyphen`, inserted runs kept, **deleted runs (`w:del`) skipped** with a warning. Requirement IDs split across runs (`FR-` + `012`) are joined.
   - **PDF:** pages in **page-tree order** (PR30-r1): the trailer's (or the cross-reference stream's) last `/Root` → `/Pages` → `/Kids` (a direct or indirect array, PR30-r3; depth ≤ 64, no cycles; a leaf that is not a page, an unresolvable `/Kids` or a tree with no content streams falls back to file order) → each page's `/Contents` (one stream, an array, or an indirect array). Objects are read from the whole file with later definitions replacing earlier ones (incremental updates) and from object streams (`/Type /ObjStm`), so the physical order of streams and obsolete or unreferenced streams do not affect the text. Only when no page tree resolves are streams read in file order, with the warning `pdf-page-order-unknown`. Stream data ends at its declared `/Length` (direct, or an indirect integer object); without a usable length an unfiltered stream is scanned token by token past strings and comments to its bare `endstream`, and a filtered one ends at the first `endstream` followed by `endobj` (PR30-r5). Object boundaries (`stream`, `endobj`) are found by a token scan that skips literal/hex strings and comments, structural lookups (`/Kids`, `/Contents`, `/Length`, `/Type`) run on dictionaries with strings and comments blanked, and `/Root` is read only from trailer dictionaries and cross-reference streams (PR30-r6). Page text is never filtered by substring; in file-order mode a CMap program is recognised structurally (`/Type /CMap`, or a program that starts with the `/CIDInit` procset) and skipped (PR30-r4). Text comes from content streams (uncompressed or `FlateDecode`; each stream inflated with a 50 MiB cap and the total capped at 100 MiB) using `Tj`, `TJ`, `'`, `"`, `T*`, `Td`/`TD`/`Tm` line breaks; each text line becomes a paragraph (PDF has no heading structure). Other filters give `pdf-filter-unsupported`; strings that do not decode to readable text (CID fonts without a supported mapping) give `pdf-text-encoding`. A PDF with no extractable text (e.g. scanned) is refused `pdf-no-text`, so the Analyst never works from an empty spec.
6. **Requirement IDs:** `<PREFIX>-<n>[.<n>…]` or `<PREFIX><n>` on word boundaries, any number of digits per part (PR30-r1; the number is matched atomically, so a long dotted run is linear), prefix from `FR, NFR, BR, UR, SR, REQ, AC, US, UC, TR, DR, IR, QR, CR` (case-sensitive, overridable). `SHA-256`, `UTF-8`, `ISO-8601` and the like are not IDs. IDs are read from the rendered blocks, so a lost ID is a visible failure.
7. **Output caps:** text over 16,000,000 characters is `text-too-long` (above the 10 MiB upload cap, so any accepted text file fits); more than 50,000 blocks `too-many-blocks`.
8. **Names:** `originalName` is reduced to its base name, control characters removed, at most 255 characters (the extension is kept when shortening); it is never used as a path.
9. **Errors** are `IngestError` with a fixed `code` and a fixed message; no source text, path or library message is ever in an error.

## Not in scope
- The upload route, file storage and the `spec` row write (`storagePath`, `version`): wired by M2.2 together with its "new spec version" flow, calling `ingest`.
- OCR for scanned PDFs; `.doc`/`.odt`/`.rtf`; images inside specs.
- Requirement parsing (titles, priorities, acceptance): M2.2.
