## Vault (`apps/api/src/vault.ts`)
- **Secrets (global, `vault_secret.project_id` NULL):** `anthropic_api_key`, `openai_api_key`, `github_token`, `linear_api_key`, `r2_access_key_id`, `r2_secret_access_key`, `coolify_api_token`. Any other name → 400 `invalid:name`. (R2 account ID and bucket are not secrets; they belong to the M2.4 provisioner's settings.)
- **Value rule:** a string of 16–4,096 printable ASCII characters without spaces (`[\x21-\x7e]`). Otherwise 400 `invalid:value*`. Error responses never contain the value or any part of it.
- **Encryption:** AES-256-GCM, a random 96-bit nonce per save, the 128-bit tag appended to the ciphertext. Additional data binds `devos-vault/v1`, scope (`global`), name and key version, so a ciphertext copied to another row or version does not decrypt.
- **Key:** `DEVOS_VAULT_KEY` (base64 of exactly 32 random bytes, generated on the server and kept in Coolify env, never in the repo or chat) and `DEVOS_VAULT_KEY_VERSION` (integer ≥ 1, default 1). A malformed value stops start-up with `config-vault-key-invalid` / `config-vault-key-version-invalid` (never the value). With no key, the vault routes answer 503 `vault-not-configured` and the wizard is never complete; settings still work.
- **Write-only:** the API stores and rotates values (`PUT`, an upsert) and returns only `{name, set, hint, keyVersion, createdAt, updatedAt}`. `hint` is the last 4 characters (stored in the new `vault_secret.hint` column so a list never decrypts). **No route returns a value.** Plaintext leaves the vault only through `Vault.reveal(name)`, for server-side consumers (runtimes, provisioner, server agent). `reveal` refuses a row sealed under another key version (`vault-key-version-mismatch`) or a tampered one (`vault-secret-corrupt`).
- **Key rotation** (re-encrypting every row under a new version) is not in scope; it needs its own decision card when first wanted. Rotating a *secret* is just saving it again.
- **Audit:** each save writes `audit_event` `vault.secret.saved` or `vault.secret.rotated` with `{name, keyVersion}`: never the value or hint.

## Settings (`apps/api/src/settings.ts`)
- **App settings (singleton `app_settings`):** `anthropicCapUsd`, `openaiCapUsd`, `defaultProjectCapUsd` (USD 0.01–10,000, at most 2 decimals, number or string; returned as `"15.00"`), `defaultLanes` (1–`maxLanes`, ≤ 3), `deadlockAttempts` (1–5, default **3** = Sonnet, Sonnet, Opus). `maxLanes` is read-only here. Unknown fields → 400 `unknown-field:<k>`; an empty body → 400 `body-empty`; a bad value → 400 `invalid:<field>`; nothing is written on any 400.
- **Wizard caps step** (`PUT /setup/caps`) requires all three caps (`missing:<field>`) and stamps `caps_confirmed_at`. The settings page (`PUT /settings`) accepts any non-empty subset and also stamps it.
- **Project settings** (`PUT /projects/{id}/settings`): `capUsd` and `lanes` (1–3). Unknown project → 404 `project-not-found`; archived → 409 `project-archived`.
- **Audit:** `settings.updated` / `project.settings.updated` with the changed field names.
- **Timeouts (ADR-0011 §9):** every database operation runs in a transaction with `timeout` and `maxWait` = `DEVOS_OUTBOUND_TIMEOUT_MS`. No retries.
- **Fail closed:** any store or driver error → 503 `settings-store-error` / `vault-store-error`. A driver message is never returned or logged (it can quote a value). Without `DATABASE_URL` + `DEVOS_POLICY_HMAC_KEY` (M1.2 runtime rule), the settings routes answer 503 `settings-not-configured`.

## Routes (added to `apps/api/openapi.yaml`; all `session`, deny by default)
| Route | Notes |
|---|---|
| `GET /setup` | `{capsConfirmed, vaultConfigured, secrets: [{name, set}], complete}`; complete = caps confirmed, vault configured, every secret set |
| `PUT /setup/caps` | Wizard step 1; all three caps |
| `GET /settings` · `PUT /settings` | Settings page |
| `PUT /projects/{id}/settings` | Project cap and lanes |
| `GET /vault/secrets` | One metadata entry per secret name, set or not |
| `PUT /vault/secrets/{name}` | `{value}` → `{secret: SecretMeta, rotated}` |

Every state-changing route goes through M1.2's CSRF checks (Sec-Fetch-Site, Origin/Referer, `X-Devos-Csrf`). A body-parser failure (malformed JSON, too large, wrong type) answers a fixed code (`body-invalid-json`, `body-too-large`, `body-unsupported-type`): the default handler could echo the parser message, which quotes the body.

`vault_secret.hint TEXT NULL` (check: NULL or 4 characters) · `app_settings.deadlock_attempts INTEGER NOT NULL DEFAULT 3` (check 1–5) · `app_settings.caps_confirmed_at TIMESTAMPTZ NULL`. The previous release keeps working against it.

## Dashboard (wizard and settings pages)
- `/setup`: step 1 caps (three fields, prefilled 15.00), step 2 one write-only field per secret (`type=password`, `autocomplete=off`), showing `•••• <hint> · saved <date>` once set, with "Replace" to rotate. The field is cleared after each save and the value is never put back in the page, state or URL.
- `/settings`: caps, default lanes, deadlock attempts; per-project cap and lanes once the project list is real (M2.x; mock projects are read-only).
- **Browser → API (M1.3 deferred this to "the first state-changing screen"):** the dashboard calls the API directly from the browser, so the API still sees KK's tailnet peer (no proxy, M1.3 decision).
  - The API answers CORS (`apps/api/src/cors.ts`) only for an exact `DEVOS_ALLOWED_ORIGINS` entry, with credentials (methods GET/PUT/POST/DELETE; headers `content-type`, `x-devos-csrf`, `x-request-id`; preflight cached 10 min). Any other origin gets no CORS headers. CORS is not access control: identity, session and CSRF checks still run on every request.
  - **M1.2 CSRF rule refined:** the dashboard and API are the same site on different ports, so the browser sends `Sec-Fetch-Site: same-site`. That is accepted **only** together with an exact allowed `Origin`; `cross-site` is still always refused, and the Origin and CSRF-token checks are unchanged.
  - The dashboard CSP adds the API origin (`DEVOS_API_ORIGIN`, an exact `http(s)://host[:port]`; anything else is ignored) to `connect-src` only. Without it the pages say the API is not configured.
  - Sign-in (`POST /auth/session`) runs when a page loads; the CSRF token is held in memory only. Every call has a 10 s timeout (ADR-0011 §9) and `redirect: "error"`.
  - Release: set `DEVOS_API_ORIGIN` on the dashboard and the dashboard's origin in the API's `DEVOS_ALLOWED_ORIGINS`.
- Escaped output only (M1.3 `no-raw-html` lint), strict nonce CSP unchanged otherwise, phone layout (390×844).
