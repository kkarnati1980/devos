# ADR-0006 — Policy engine, fail-closed budgets, receipts, worktree rules and typed provenance (adapted from ruflo, MIT)

- **Status:** accepted (4 Nov 2026, KK approval; Architect under D10). Applies to M1.1, M1.5, M1.7, M2.3, M3.2, M3.6, M4.3.
- **Context:** DevOS gates are enforced in several places (run limits in M1.5, approval cards in M2.3, migration holds in M4.3, Release SHA checks), each with its own logic. Unmetered calls could bypass the USD 15 caps (O5), the audit log (DV-NFR-06) is editable without detection, and memory types (DV-NFR-08) do not say who asserted a fact. ruflo (github.com/ruvnet/ruflo, MIT, commit a3d45e6, v3.70.0) contains a small, dependency-free policy engine (`v3/@claude-flow/security/src/policy`: engine, evaluator, envelope, canonical, types; about 900 lines using only `node:crypto`) designed in its ADR-324, typed provenance (ADR-323), and worktree rules (`v3/@claude-flow/codex/src/worktrees`).
- **Decision:**
  1. **One policy decision point** (new module M1.7, `packages/policy`). Every consequential action is evaluated as identity + action + resource + evidence + envelope + approval + budget → `allow | deny | require_approval`, persisted with a receipt before the action runs. Deny overrides approval and allow. Unmatched actions are default-deny in `enforce`.
  2. **Capability envelopes:** a child run's envelope (tools, paths, network, cost, tokens, concurrency, expiry) can only shrink from its parent's; violations are always blocked.
  3. **Approvals:** scoped, expiring, revocable, limited-use. Only KK issues them, identified by his Tailscale-authenticated dashboard session (O4). Agents can never approve themselves.
  4. **Fail-closed budgets:** a budgeted call must declare its cost/token reservation before it runs; a missing figure is a deny. Usage is reconciled after the call. The provider caps (USD 15 Anthropic, USD 15 OpenAI) stay the final ceiling.
  5. **Hash-chained receipts:** each decision row stores canonical-JSON SHA-256 `hash` and `prevHash`; changing any byte breaks verification. An HMAC key stored outside the repo authenticates the chain.
  6. **Worktree rules (rules only, not code):** writers never share a checkout; read-only workers may; one integration owner holds lockfiles and shared manifests; dependency cycles or missing dependencies fail before any worker launches; dirty worktrees are kept for recovery and never force-deleted.
  7. **Typed provenance:** every memory, evidence and fact record carries `provenance ∈ {kk_approved, system_observation, tool_result, agent_output, user_claim, unknown}`. `kk_approved` covers the approved requirements file and answered decision cards. An unapproved claim or agent output is never promoted to evidence silently.
- **Guards:**
  - **Rollout:** new default-deny rules run in `observe` mode (record would-deny, do not block) from M1.7 merge until G3. KK approves the switch to `enforce` at G3 after reviewing the observed denials. The five gates, envelope violations and the D7 PreToolUse deny hook are **always enforced** from day one.
  - **A policy denial is not a failed attempt.** It does not advance the Sonnet → Sonnet → Opus ladder (D6) or the 3-attempt deadlock rule (D10). It pauses the task and raises a card.
  - **A budget stop pauses at the last checkpoint** (DV-NFR-01) and raises a card. It never kills a run mid-edit.
- **Licence (D13):** ruflo is MIT. Lifted files keep a header naming the source file and commit, and `THIRD_PARTY_NOTICES.md` carries ruflo's full MIT licence text. The devos repo licence is unchanged; MIT permits use inside proprietary code with the notice kept.
- **Consequences:** one auditable authority for gates, spend and approvals; tamper-evident audit trail; about 2–3 extra Builder sessions inside P1. Each consequential action adds one locked database transaction (ruflo measured ~23 µs locally, excluding disk). Rules must be written before `enforce`.
